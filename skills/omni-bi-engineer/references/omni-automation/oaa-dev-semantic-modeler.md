# Build a bounded Omni Topic

Accept one assignment from the Omni Artifact Accelerator. Return to the calling agent with the verified Topic or the smallest actionable gap. This skill supports existing warehouse bindings and one development branch. The caller retains the product conversation and A–F gates.

**Inspect.** Preserve the original source/domain IDs, source definitions, review references, intended viewers, data grain, source population, selected Topic and target identity. Inspect accessible Topics, views, measures, keys, joins, filters and existing security rules. Confirm visibility with a model-authorized principal before treating a Topic as absent. Existing DMA scope or a conflicting model owner routes any model change back to its owner.

**Design.** Reuse verified physical views. Select explicit dimensions, a reviewed additive measure or count where its grain supports it, and necessary reviewed relationships. Preserve defined null semantics, join direction, cardinality, fixed/source filters and access rules. Keep a per-source-object disposition and comparison cases. Record ambiguous, unsupported and restricted constructs as gaps. A Topic that still lacks a required definition remains a partial candidate.

**Protect the audience.** Establish who may open the document, who may use the Topic or a protected field, what rows each audience may receive, and which on-screen controls users can change. Reuse approved model grants and user-attribute values. Record direct and inherited content access, connection/model roles and any elevation. Keep model grants, row access and user-editable controls separate. Route missing identity mapping, grant provisioning or content-sharing decisions to the owner. An analyst's successful query cannot verify a restricted viewer.

**Prepare the branch change.** Inventory the effective native tools. A host offering a branch-aware model editor can use it within the actual operator's approved scope. Confirm a distinct development branch ID, its shared-model ancestry and connection, the author identity, complete file identities/checksums on shared and branch, and the intended Topic filename. Compare the proposed change against that baseline. Preserve existing files and original source identifiers. If branch editing is unavailable, return the exact reviewable file and diff with destination, assumptions and native steps using the available private output surface. Mark application and verification pending. The native flow requires neither a cloned repository nor an uploaded script.

**Apply and observe.** Only apply the exact authorized patch to the pinned development branch. Record each operation and read back the branch plus shared state after a response or timeout. Reconcile an unknown write before any retry. Run native model validation against the branch. Re-read the Topic in that branch and query it explicitly, checking independent totals, grouped slices and applicable restricted-viewer behavior. Distinguish evidence from the host and any offline checks. Return the branch ID, effective Topic name, revision/fingerprint, governed fields, validation results, sample-free comparison evidence, gaps and next action. Model merge, publication, permission grants and upstream transformations have separate owners and authorization.
