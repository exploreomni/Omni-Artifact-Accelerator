# Route Stage A

Keep the user's artifact request and chosen surface in this chat. Inspect the current source, destination, effective user and assigned native Agent and Skill tools. Load /oaa-dev-topic-handoff for Topic, saved-query and control evidence. Load the existing coordinator skill for the A–F journey. If you are already the coordinator, continue the engagement yourself.

1. **Check for a handoff first.** Retain the original DMA continuation and semantic review identities, selected Topic, version, branch, source scope and unresolved items. Resume the same engagement. A usable Topic goes directly into Topic-backed analysis. Return a missing calculation, inaccessible field, undeployed candidate or security change to the recorded model owner with its affected consumers and comparison cases. A failed lookup leaves that owner in place.
2. **Inspect the existing model.** On an OAA-only engagement, identify the model and branch, intended audience, accessible Topics, relevant views, and evidence of grain, joins, covered questions and access. Reuse a suitable Topic. Where model visibility is incomplete, ask the model owner to confirm availability. A single person's empty search result cannot establish absence.
3. **Offer the bounded modeling lane.** With verified existing physical data and no suitable Topic, offer to build a branch Topic. With legacy semantic definitions, involve the relevant source specialist to inventory its supported original IDs, metric definitions, joins, filters and policy. Ask once about the material missing choice, such as the intended audience or who owns the definition. Carry existing answers forward.
4. **Delegate to one owner.** For the standalone lane invoke the assigned /OAA Omni Modeler Agent tool and pass the selected origin, model, branch, principal, physical bindings, scope, target artifact, expectations, policy and evidence references. The modeler loads /oaa-dev-semantic-modeler. Call the registered Agent tool and inspect the actual return. On a compatible dual installation the operator may explicitly bind its qualified existing modeler to this role. Keep a DMA-owned handoff on the DMA/model owner's workflow. A tool chip, mention or returned plan alone is not evidence of execution.
5. **Handle dependencies.** If physical data, keys, transformation, history or a required upstream security policy is missing, prepare a portable request to DMA or the customer's upstream owner. Include the source/target identity, affected queries, missing field or grain, independent expected outcome, and the resume point. Keep a declined modeling step pending. If a DMA candidate arrives during standalone work, compare its exact destination, objects, definitions, policies and dependencies. Preserve competing versions and request a model-owner decision on any conflict.
6. **Continue from verified semantics.** Record any tested host limitations. Pin the selected Topic, actual model revision/branch, current user and readback. Hand the Topic and analysis scope to the Evidence Analyst. Bind all affected App panels, dashboard queries and controls to the selected Topic. Preserve discovery, narrative, product interview and design selection. After selection, continue the build from the reviewed brief in the same chat. Track native model validation, data reconciliation, restricted-viewer checks, artifact wiring, creative review and release independently.
