# Independent spatial QA

Use this reference for an affected spatial model/App review. Read the original brief, source geometry/dimensions, query contract and selected design before inspecting implementation results. Derive expectations independently, freeze the relevant candidate/source pins and use existing [design evidence](design-evidence.md) cases and lanes. There is no new spatial pass flag, aggregate craft score or approval system.

The implementer may self-review but cannot claim independent assessment. A designer judges the actual composition and task usefulness; QA checks source meaning, outcomes and evidence. An installation or curriculum record establishes availability, not modeling expertise.

## Select checks by the task

| Concern | Independent expectation | Meaningful check and limit |
| --- | --- | --- |
| Fidelity and dimensions | Original units, axes, measured versus illustrative dimensions, hierarchy and permitted tolerance when supplied. | Compare bounds, part relationships and relevant transforms to the brief. Do not derive expected dimensions from the generated asset or invent a precision requirement. |
| Parameter changes | Expected counts/extent from original repetition rules; stable identities for retained parts. | Change a consequential parameter and check affected count/bounds plus preserved IDs. An unsupported operator remains unsupported, even when the intended shape is easy to describe. |
| Data identity and meaning | Approved source keys, entity cardinality, grain, filters, timestamps, denominator and null rules. | Check duplicate/unmapped IDs, unknown versus zero, absent-in-partial versus excluded/restricted entities, and exact selected evidence. Never infer callback shape from a query export. |
| Visual encoding | A stated mapping from governed values to position/size/color, including signs, zero and unknowns. | Independently check mapping logic; actual perspective, lighting, occlusion and label legibility need rendered observation. Equal correct labels can coexist with misleading geometry. |
| Inspection and return | Named useful views, stable selection, camera context, focus/list route, reset and supersession rules. | Exercise entry → select → evidence → return, then an applicable delayed/failing input or changed-asset case. Do not replace a requested pending selection with a default merely because data arrives later. |
| Tour and lifecycle | Meaningful stops, immediate exact evidence, interruption, reduced/static equivalent and hidden/disposed behavior. | Verify no unwanted resumption on return, cancellation/cleanup and explicit restart. A storyboard or stop list is not exercised camera behavior or proof of comfort. |
| Constrained space and access | Applicable wide/narrow and short-height contexts; keyboard/non-canvas path to the same information. | Inspect selected evidence, controls and focus in the exact candidate. Source inspection cannot establish visual contrast, target size, screen-reader usability or effective role access. |
| Asset delivery | Authorized source and transformation history, approved output profile, candidate hash and independent validation receipt. | Ensure consumer bytes match promoted bytes. Format validation is separate from rights, safe parsing, runtime compatibility and visual quality. Do not open/execute untrusted assets to obtain a pass. |

For the curriculum terminal sample, derive each ratio from its numerator/denominator; retain an unknown result when the numerator is absent. A complete fleet or all-assembly coverage result is unsupported. Keep independent expectations separate from modeler/compiler computations so a shared implementation mistake cannot validate itself.

For dimensional bars, trends and layered comparisons, use the affected obligations
in [dimensional visualization craft](../../omni-design-systems/references/dimensional-visualization-craft.md):
shared scales, signs/zero/ties, gaps, actual/target/forecast meaning and constant
decorative depth. Include missing-value labels and a long-label case at constrained
width/height. Source mapping checks cannot establish perspective, occlusion or
legibility; exact tooltips do not excuse misleading marks.

## Keep evidence lanes truthful

- **Specification/source review:** can identify missing intent, faulty mappings, unreachable states or inadequate lifecycle logic. It cannot prove execution or appearance.
- **Local numerical/structural checks:** can compare exact dimensions, counts or values for tested inputs in an approved environment. They do not prove native callback behavior, rendering or security isolation.
- **Rendered craft/responsive/accessibility observation:** needs the exact candidate and an authorized actual observation method. A renderer's existence, image signature or nonzero canvas size is insufficient. A still image does not establish interaction.
- **Native behavior/access/performance:** needs the real target, exact candidate/assets/runtime, observed input and exercised behavior. Separate effective access and actual device performance from simulated success.
- **Participant/business evidence:** requires attributable real observations or acceptance. An agent exercise is not customer satisfaction or a user study.

Record the applicable scope and unrun/blocked cases in the existing QA structure. Do not multiply every lane across every part: select obligations by task and claim. If rendering or native observation is prohibited, continue permitted checks and leave those outcomes unrun. A native dashboard requirement does not inherit an App viewer pass; retain its own verified capabilities and unsupported behavior.

## Focused correction and release handoff

Retain the initial failed candidate and evidence; retest the same affected obligation on the revised exact bytes. A material geometry or mapping change invalidates affected dimensional/numerical/interaction evidence; a runtime, asset-loader or dependency change may also affect security and native behavior. Keep unaffected expectations when justified and avoid broad reruns without a new concern.

Before delivery, reconcile the selected current brief, model/parameter source, asset, identity mapping, runtime and QA pins. Historical passes remain historical. Report useful outcomes and the smallest unresolved requirements; publication/readback alone cannot close visual, runtime, usability or security claims.

Security execution is owned by the qualified harness/operator under the shared [dependency policy](../../omni-artifact-accelerator/references/dependency-policy.md). Check that required approval/isolation/quarantine evidence exists before dependent work, without treating an agent manifest as authority. No Blender route, unapproved package import/install or host-execution fallback may be used to run a QA case. These documents supply no approved isolation runner; missing authority or capability blocks that case rather than all unaffected source review.
