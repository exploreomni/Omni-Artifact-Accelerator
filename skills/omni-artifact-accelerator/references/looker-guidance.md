## Dashboard and App application

Capture once, then share the same source scope, metric contract, query bindings and brand decisions across the selected surfaces. The dashboard designer preserves analytical groupings and supported controls. The App designer organizes tasks and states; the App engineer binds them to actual governed queries and an inspected runtime. Do not require an intermediate dashboard for an App-only engagement.

For `both`, keep separate documents, candidate files and surface evidence. A dashboard image or receipt cannot verify an App's interaction behavior. Unsupported source actions remain visible work even if the replacement looks good. Use branding's existing company-website intake and asset provenance; preserve source metric meaning while recording visual improvements explicitly.

The shipped App authoring path's exact boundary is in [the native App contract](../../omni-app-engineer/references/native-app-contract.md). Current product and transport labels are separate; verify the actual operation before live use. No article, test or local readback grants native acceptance or publication.
