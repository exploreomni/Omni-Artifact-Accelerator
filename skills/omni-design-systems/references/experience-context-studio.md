# Studio: one task, three experience structures

Use this bounded exercise after an experience brief needs a concrete selection, or when feedback says the result feels like a generic dashboard. The [self-contained specimen](../assets/experience-context-studio.html) is original, synthetic and local; it is **not native Omni**, a production starter or proof of rendered quality. It embeds no external assets and makes no network requests. Do not build three alternatives for an ordinary correction or faithful migration merely because this studio shows three.

## Lock what must not change

- **Audience:** library operations analyst.
- **Question:** “Which branches explain the monthly circulation change?”
- **Primary action:** inspect a branch's monthly evidence.
- **Organization:** fictional Common Thread Public Library. Original text identity; no real customer's assets or rights are implied.
- **Metric:** recorded checkout events excluding renewals, monthly counts; not unique patrons, daily-normalized activity, program impact or a target comparison.
- **Default comparison:** March → April 2026, all three branches, no preselected branch. Only the four supplied complete synthetic months are available.

| Fictional branch | January | February | March | April | March → April |
| --- | ---: | ---: | ---: | ---: | ---: |
| Central | 2,100 | 2,250 | 2,400 | 2,500 | +100 |
| Riverside | 1,500 | 1,560 | 1,600 | 1,580 | −20 |
| Hillview | 980 | 1,040 | 1,100 | 1,220 | +120 |
| Total | 4,580 | 4,850 | 5,100 | 5,300 | +200 |

The default increase is approximately 3.9%; it is not shared by every branch. January → April changes are +400, +80 and +240, totaling +720. Those differences do not establish a cause. The specimen's `library-fixture` JSON is the exact machine-readable copy of this fixture; its small `library-domain` calculation/state functions are inspectable. Do not broaden its fixed-fixture coverage into a missing-data, access, live-query or production-scale claim.

## Diagnose the weak start before styling

The annotated initial composition gives equal space to current circulation, percentage change, branch count and month count, followed by a current-volume bar chart. It has correct values but no branch-evidence action.

Record these concrete defects:

1. Branch count and supplied-month count compete with the actual question. Make **signed branch contribution** the main evidence hierarchy.
2. Current-volume bars answer “which branch is larger,” not “who explains the change.” Pair endpoints and use one signed scale with an explicit zero.
3. A selected branch must reveal the four observed months and exact values. Renaming a button “Explore,” adding a hero or recoloring the same layout does not create that behavior.

The period is available in the shared laboratory controls, but the weak artifact separates it from the marks. The improved treatments repeat it beside their claim and selected evidence. The counterexample is intentionally weak; it is not a negative accessibility test or a native rendering observation.

## Translate reference qualities into different structures

These are original quality targets from the package's [pattern atlas](experience-patterns.md), not copied designs or claims about another product. Resolve the real user's preference through the [experience brief](experience-brief.md); do not infer it from the industry.

| Treatment / quality to translate | Concrete composition and state choice | Tradeoff and selection reason |
| --- | --- | --- |
| **A. Direct workspace / precision** | One screen: total change and scope, signed branch rows with paired values, adjacent selected four-month chart/table. Restrained system typography and alignment put evidence first. | Prefer for frequent investigation or direct access. Single-screen and imagery-free are valid final choices, not unfinished brand work. Narrow layout stacks evidence; its full task still fits without a new destination. |
| **B. Branded entry → investigation / welcoming editorial identity** | Original typographic wordmark, serif display rhythm and an open intro lead to a separate branch notebook. Named branch choices then give the selected evidence the full working area. The introduction and investigation are different states, not a hero pasted over A. | Prefer when the user explicitly values a branded entry. The extra step has a cost; return preserves branch/period and the exercise includes a direct alternative. No photography or remote font is required. |
| **C. Narrative → inspectable evidence / guided explanation** | Reader-controlled chapters change from total to contributors to selected branch. The claim updates with period; choosing any contribution jumps to evidence. “Skip to branch evidence” always bypasses the sequence. | Prefer when interpretation order helps the reader. No autoplay or forced chapters. A stable question and explicit counterexample matter more than theatrical transition. |

All three share the same data, audience, question and primary action. Choose one for a real handoff; do not merge all three into an oversized application. A source migration's behavior and selected surface remain binding. An attractive redesign does not accept a parity difference or authorize an App substitution for a native dashboard.

## Turn the selection into a bounded handoff

Use the following as a **human-readable worked card**, not a new helper/API schema. Copy its decisions into the existing engagement brief, selected design/brand and named requirements. The sample selects **A** as a working recommendation for a frequent analyst; that preference is invented for training, not a user acceptance record.

```text
Selection: A — direct workspace
Decision basis: repeated branch investigation; fastest path from change to monthly evidence
Rejected tradeoff: B adds an entry step; C adds interpretation order the analyst does not need
Invariant: same metric, population, endpoint comparison and primary action
Art direction: compact evidence instrument, system type, one selection accent, no imagery
Required states: no branch selected; named branch selected; period changed; reset
Useful detail: four monthly counts + common-scale path + exact endpoint change
Preserved state: branch identity and endpoints during layout/treatment navigation
Usable space: proposed 1024 × 600 App area after host chrome; not a measured device
First view: scope, signed change and a branch Inspect action; evidence may continue below
Scroll: one constrained content region; chart/table horizontal overflow only when needed
Return: named branch control and originating scroll; no selection reset from resizing
Target mapping: qualify the chosen native surface/query bridge before implementing
Observed: source specification only
Not observed: rendered fit, native interaction, assistive technology, participant success
```

| Named requirement | What the producer must hand off | Review case and ownership |
| --- | --- | --- |
| `CT-01` — explicit question and scope | March → April, all three branches, checkout-event units next to the claim. | Analyst independently expects 5,100 → 5,300, +200; QA checks the same scope in the current candidate. |
| `CT-02` — explanatory comparison | Central +100, Riverside −20, Hillview +120, common signed zero scale and paired endpoints. | Designer specifies hierarchy/scale; engineer implements it; QA reconciles contributions and verifies the actual chart mapping. |
| `CT-03` — useful primary action | “Inspect Riverside” opens named four-month evidence: 1,500 / 1,560 / 1,600 / 1,580. | Designer owns detail/return; engineer retains identity; reviewer checks that detail adds this evidence rather than repeating the summary. |
| `CT-04` — current state | Selected branch persists when period changes to January → April; narrative/amounts become +720 total and +80 Riverside. | Engineer owns transitions and stale-state suppression; independent QA checks preserved identity and revised amounts. |
| `CT-05` — deliberate identity | A uses a compact original text identity without imagery; B uses a materially different editorial composition. | Branding records the fictional exercise provenance. For a customer, reuse their actual asset/website decisions; this invented wordmark is not an allowed substitute. |
| `CT-06` — equivalent access | Named controls, meaningful focus, exact table, reset and immediate reduced-motion equivalent. | Motion designer specifies purpose/static state; engineer implements it; QA and designer retain separate source, rendered/native and assistive-technology observations. |
| `CT-07` — usable short-height workspace | Assumed usable 1024 × 600 and 1180 × 680 areas, host chrome not measured; first-view priority and deliberate continuation. | Designer specifies wrapping and scroll; engineer preserves readable actions/evidence; QA records actual dimensions and fit only when observed. |
| `CT-08` — optional presentation aliases | Exercise-only authorization maps stable source IDs to fictional display names; detail preserves source identity and values. | Branding owns authorization/mapping; engineer keeps aliases out of arithmetic/joins; QA challenges collisions and identity drift. |

The orchestrator or direct-invocation lead resolves the brief and selected surface, records unresolved choices and assigns bounded work. The analyst owns meaning and independent expectations. Designer, branding and motion roles own their respective decisions; engineering does not silently change the selected architecture. After implementation, the designer returns to the **exact candidate** for craft review, and QA independently checks named cases. Neither role treats a source pass as native acceptance. Small edits reuse prior answers and do not reopen the entire studio.

## Motion, return and static equivalence

The specimen proposes 220ms destination/selection emphasis and a moving endpoint highlight on a fixed January–April chart. Values commit immediately; branch paths and the common 0–3,000 checkout scale do not morph. A newer selection replaces the earlier state; no count-up numbers or playback gate. System reduced motion and the local Motion switch suppress animation while retaining controls, labels, focus destinations and exact tables.

Treatment switching preserves the selected branch and period. B remembers introduction versus notebook; C remembers its chapter. The primary Inspect action in C goes straight to the selected branch's evidence. “Back to branch choices” restores the originating named control and scroll where retained; a treatment first reached with an existing selection has a named-choice fallback. Reset explicitly returns to weak start, March → April, source names and no selected branch; the laboratory frame and motion preference remain independent. This is local in-memory state; it is not saved-server state, a share link or a native routing promise.

## Carry context through a cramped laptop handoff

The specimen's **Usable local frame** offers natural height, up to 1180 × 680 and up to 1024 × 600 CSS pixels. Width is capped by the surrounding page. These are proposed content-area constraints, not measured screen sizes, browser emulation or native-host observations. The controls and working content share one deliberate vertical scroll region. Short-height rules tighten secondary spacing; container rules stack list/detail when their content width is insufficient. Exact evidence remains reachable rather than forcing the whole task above the fold.

Use only the relevant dimensions in a real engagement. Record what host chrome or side panel has already been subtracted, zoom and whether the result is assumed or observed. For A, prioritize the question/scope, total change and an Inspect action. For B, prioritize the entry's useful action rather than a fixed-height hero. For C, keep chapter/evidence navigation reachable. Review long names, wrapped controls, return focus and horizontal chart/table overflow; do not rescue a failed composition by making all type tiny. A container rule or source calculation does not establish actual rendered fit.

The signed branch bars encode **additive change**, with a shared zero and scale. The line encodes observed monthly checkout counts with a fixed 0–3,000 scale. The background and wordmark encode no data. This distinction is the reusable lesson: a connector, vessel or spatial shape must either have an explicit field/unit/scale/identity contract or remain clearly decorative. Nothing in this dataset supplies geography or physical flow.

## Three context failures to rehearse

**Display aliases are separate authorization.** The optional exercise mapping is `central → Civic Hall`, `riverside → Waterfront`, `hillview → Summit`. These names, the organization and permission statement are invented training material. The fixture retains Central/Riverside/Hillview; `riverside` remains the selected ID and April remains 1,580. The detail exposes original name and ID. Arithmetic uses original branch records, never the alias. For real work, follow [demo presentation](../../omni-branding/references/demo-presentation.md), preserve the exact approved mapping as an explicit dependency and reject conflicting/missing mappings rather than grouping by a label. A logo sourcing answer is not alias permission.

**A superseded “current” heading is still history.** The specimen names an invented v1 roomy branded-entry decision and a later v2 direct-workspace working recommendation with a short usable area. A v1 packet is stale for dependent composition work even if its file is intact. Reconcile the selected intent/current-context references and explicit inputs using the existing workflow, retain v1 as superseded evidence and regenerate the handoff. Do not rewrite a sealed review or infer new acceptance. This example is a decision-precedence exercise, not an alternative index schema.

**Equal values do not mean equal transport contracts.** `library-context` contains a synthetic export with display headers and a separate synthetic callback-shaped object with semantic keys. `LibraryLessons.readExample` accepts only its declared teaching shape and required typed fields; supplying export rows as a callback, a missing field or explicit null throws. The study's analysis still uses `library-fixture`; this adapter is not connected to Omni. The real [native data-input contract](../../omni-app-engineer/references/native-data-input.md) must separately retain verified APIs, row envelope/keys, status lifecycle and observation provenance. A mocked shape cannot qualify native behavior. Do not add guessed fallback property names until they appear in an explicitly supported contract.

Keep these decisions in existing structured requirement values and selected design dependencies. The analyst owns immutable source meaning; branding owns the presentation authorization; engineering owns input adapters; the designer owns the available-space and return contract. An unresolved native callback does not block independent layout work, but does block claiming native runtime success.

## Focused no-browser review exercise

Do the permitted source/parse checks only when rendering is prohibited. Record these as **source-rehearsal expectations**, not user task completions:

1. Read `library-fixture` and independently calculate the two endpoint cases above. Confirm all three treatments call the same derivation rather than changing data to make a composition look better.
2. Trace Inspect Riverside in A → switch to B → enter notebook → switch to C → skip to evidence. Verify the same branch/period is retained and the exact detail stays attributable. Inspect the declared focus targets and visible selected states.
3. Trace January → April and confirm the headline no longer says Riverside declined. Reject a stale statement even if the layout is attractive.
4. Inspect CSS narrow rules, accessible table/overflow regions, reduced-motion rules, interruption behavior, escaped chart-label path and absence of external requests. A source assertion cannot establish physical fit, actual focus traversal or a rendered transition.
5. Review the selected treatment in grayscale conceptually: its structure should remain distinguishable by grouping, proportion and state architecture. If only colors differ, revise the concept before presenting it as a meaningful alternative.
6. Select the cramped frame in source/state rehearsal; inspect its width cap, 600px height, readable control rules, container adaptation and deliberate scroll. Trace Inspect → Back and the source control/scroll restoration. Leave physical fit, actual scrolling and focus traversal unobserved.
7. Select `riverside`, enable aliases, switch treatment and change endpoints. Confirm the selected ID and exact values are unchanged and detail reveals source identity. Reset must restore source names. Try an invalid teaching callback/missing field/null against `LibraryLessons`; it must fail instead of yielding zero.
8. Hand a second role the superseded v1 decision alongside the v2 selection. It should identify the current choice, carry runtime/alias inputs explicitly and name unobserved lanes. Do not accept “the old file still hashes correctly” as freshness.

**Closeout card:** chosen mode and reason; exact handoff/candidate references; named requirements; observed source findings; remaining rendered/native/access/participant evidence; publication status separately. Do not claim all three treatments are validated, that every App needs a branded intro, or that an imagery-free/direct experience lacks craft.
