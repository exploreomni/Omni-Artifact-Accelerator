# Optional control-design study and source guide

Checked **2026-10-23** through official/provider pages and connected Udemy search/content metadata. This is a maintained selection for [control craft](control-craft.md), not a copied curriculum or required course. No enrollment, playback, purchase, installation or course completion was performed. Recheck access when recommending enrollment and implementation-sensitive facts when adopting an API. Durable principles, provider terms and target capabilities are different evidence.

## Choose a source for the question

| Question | Primary reference | Use and limit |
| --- | --- | --- |
| Button hierarchy, known choices or typed options? | Fluent 2 [Button](https://fluent2.microsoft.design/components/web/react/core/button/usage), [Dropdown](https://fluent2.microsoft.design/components/web/react/core/dropdown/usage), [Combobox](https://fluent2.microsoft.design/components/web/react/core/combobox/usage) | Compare purpose/state anatomy; do not import React, vendor styling or an option-count rule by implication. |
| Custom choice and tab keyboard behavior? | W3C APG [Combobox](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/) and [Tabs](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/) | Distinguish active option, committed value and dismissal. Automatic tab activation requires suitably immediate panels. Examples need browser/assistive-technology testing; native controls may be simpler. |
| A usable search form? | [USWDS Search](https://designsystem.digital.gov/components/search/) | Study labels, preserved query, HTML and tests. Site search is not automatically the right analytical-filter pattern. |
| Expressive semantic controls? | web.dev [Building a button component](https://web.dev/articles/building/a-button-component) | Study semantic HTML, CSS states and preferences. Check sample rights and host support before adopting code. |
| Embedded layouts and tables? | MDN [Container queries](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Containment/Container_queries); Carbon [Data table](https://www.carbondesignsystem.com/building-blocks/core/components/data-table/guidelines) | Separate pane from viewport size, and page from comparison columns. Vendor sizes are examples, not Omni defaults. |
| An accurate target-size claim? | W3C [WCAG 2.2 Target Size (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) | AA is 24 × 24 CSS pixels with defined exceptions, including spacing. Larger targets are a product choice; source review cannot certify conformance. |

These principles and package recommendations are not observed Omni features. Retain title, URL, checked date, observation type and rights in engagement research when a source informs a consequential choice. Read only relevant material; a listing does not prove its full content or interaction was inspected. A reference grants no dependency, media or network permission.

## Rights, freshness and reuse

Derive original rules and synthetic exercises. Do not redistribute course videos, transcripts, assignments, screenshots or assets by default. Inspected web.dev welcome pages identify Apache 2.0 for code samples unless otherwise noted; check the specific sample and retain required notices if adopted. OpenLearn identifies CC BY-NC-SA 4.0 with third-party exceptions, so free reading is not unrestricted commercial reuse. Other provider availability likewise grants no blanket reuse rights. No third-party code, videos or lesson excerpts are bundled by this guide.

Recheck when a recommendation depends on changed price/access, component APIs, browser support, licensing or required Omni capability. Retain checked dates and unresolved observation limits instead of claiming permanent freshness. Broken/inaccessible sources are gaps, not instructions to enroll, install, play media or block unrelated delivery. The [six focused lessons](experience-curriculum.md#focused-control-practice) connect optional reading to existing roles and review records.
