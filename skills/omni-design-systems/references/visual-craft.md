# Visible design, resolved handoff and craft review

Use for substantial new experiences, material redesigns, or a stated visual-quality problem. This is the package's design method, not a vendor standard, native capability claim or another permission gate. Continue authorized sketches and prototypes. For a small correction, inspect the affected component/states; for faithful migration, retain source behavior and review supported adaptations without requiring divergent redesign.

## Establish the visual question

Use the [shared experience brief](experience-brief.md) as the compact connection between the user's wording, selected direction and implementation. Retain named choices in the current intent/design records so a specialist or resumed turn receives their origin, scope and unresolved status. Resolve the actual type/image hierarchy, geometry and asset budget before handoff; general reference qualities alone leave those choices open.

Reuse audience, task, brand website/authority, metrics and target decisions. Capture the reference qualities to borrow **and avoid**, density, principal content, supporting actions, selected appearances and representative widths. “Premium” or a famous brand name alone is not a design specification. Translate it into observable choices: the opening composition, type/image scale, focal content, action hierarchy, purposeful space and a task-specific next step. For Apps, retain the selected [experience mode](../../omni-app-designer/references/app-patterns.md#choose-the-experience-mode). A focused workspace may be imagery-free; an intentionally immersive entry needs its own resolved art direction. Neither is the universal default.

For new products/reconception, follow Stage E: exactly three distinct viable products, comparable evidence and the actual user selection. A focused composition exercise may compare only the affected treatments; it does not reopen product selection. Change grouping, reading path or interaction, not just color. Show current required treatment in each relevant comparison using the same representative scope, data, long labels and consequential state. Use permitted previews; when rendering is unavailable, supply a concrete labeled storyboard/specimen and leave the rendered lane unverified. No browser/headless workaround is implied. Prose or CSS tokens alone do not establish a visual comparison.

For selected dimensional styling, use [dimensional visualization craft](dimensional-visualization-craft.md). Preserve scales, zero, gaps, series meaning and exact-value access before judging materials, light or perspective. Its static examples are illustrations of design intent, not built chart runtimes.

## Resolve the implementation handoff

Use the [current design-intent selection](../../omni-artifact-accelerator/references/design-intent.md) to bind this handoff to its brand, declared assets and surface candidate. The representative screen should contain the selected logo when required, realistic values, typography/fallback, density, primary action and consequential state together. Reuse an existing concept; a focused correction needs only its affected component. An agent's working choice is not customer acceptance.

Provide enough specificity to remove material aesthetic guesswork:

- Screens at the agreed wide and narrow sizes, with a page overview and readable detail; record the actual viewport and appearance.
- Content hierarchy, grid/containment, type roles, spacing, number treatment, chart anatomy and contextual control placement. Use resolved values in the candidate; retain justified responsive rules rather than vague ranges.
- Realistic labels/values and relevant empty/error/loading, selected/focus and partial states. Never manufacture a positive business result to make the composition compelling.
- The selected task sequence, useful information added by detail, query scope and state dependencies, return/focus behavior and reduced-motion equivalent.
- When imagery is selected: its role (atmosphere, explanation, product identity or decoration), authorized source, crop/focal point, narrow treatment, contrast, accessible description and no-image fallback. An atmospheric brand image must not imply that it depicts a demo data row, store or measured result. A typography-led composition is also valid when explicitly resolved.
- Motion along the primary journey, when useful: entry/action/destination, the identity or context preserved, interruption and immediate reduced-motion behavior. A transition reachable only after optional analysis does not by itself satisfy an expressive opening brief.
- Native mapping and gaps. Confirm supported dashboard layout, theme, label/axis and interaction settings before freezing their use. HTML comps illustrate intent; they do not authorize native DOM/CSS injection or a surface substitution. A supported adaptation may change styling while preserving the intended hierarchy and task.

Use the existing engagement schema. These are minimum evidence concepts, not a second lifecycle or an import format:

```yaml
concept: {id: concept-a, surface: app, render_refs: [], context_ref: null}
selection: {concept_id: concept-a, rationale: null, authority: working_decision}
resolved: {screen_refs: [], tokens_ref: null, chart_specs_ref: null, state_bindings_ref: null}
deviation: {intended: null, actual: null, reason: null, candidate_pin: null, designer_disposition: unresolved}
craft_case: {candidate_pin: null, viewport: null, appearance: null, state: null,
             capture_ref: null, expected: null, observed: null, finding: null,
             status: not_run, reviewer: null, correction_ref: null, retest_ref: null}
```

## Designer return loop

Review the hierarchy at the level of actual regions, not just component names. For a working view, trace the content before the main evidence, the relative emphasis of subject versus controls, the image/value relationship when imagery is selected, and the next useful question. Record an explicit disposition for each selected surface/type/imagery/motion choice. A complete component inventory or passing interaction check cannot compensate for a missing focal composition.

When using a prior artifact as a quality reference, translate its strengths into task benefits before borrowing a treatment. Layered surfaces may separate evidence, a larger subject may clarify identity, and a preview may help choose a study; gradients, portraits, scenes and cards are not independently quality requirements. Evaluate type roles and foreground/background pairs, not simply whether the reference's palette or font was copied. Keep essential period, denominator and uncertainty labels visible while moving secondary provenance or implementation language out of the primary story.

Start this loop on the [first assembled journey](experience-brief.md#build-the-first-complete-journey-early), before scaling substantial work across destinations. Engineering returns the exact assembled candidate/version, supported launch or preview target, material deviations and permitted observations. Native captures are required to establish native appearance; source or prototype evidence retains its own limits. The designer compares against the original named requirements and selected design, inspects the changed composition and records a disposition. Requirement-specific observations must identify the current asset/candidate, affected surface and state; a broad craft finding cannot stand in for an omitted logo, type treatment or primary task check. Independent QA evaluates applicable visual/behavior expectations; the implementer's own check is not independent review. Fix material findings and review the changed version. An earlier prototype capture cannot close the native lane.

Before an experience-completion claim, account for every consequential destination using the existing review: `purpose/action → dominant subject/evidence → useful detail/return → constrained state → observation or gap → correction/retest`. Review a complete drill/return path as behavior, not only disconnected screen stills. Choose representative phone, short laptop and wide contexts only where the task warrants them; a focused change does not restart all cases. Missing observation stays open rather than being replaced by a count of passed source tests.

| Craft question | Concrete evidence or correction |
| --- | --- |
| What matters first? | Opening content view exposes task, scope, focal result and next useful action. Rebalance competing cards or oversized identity areas; do not impose a universal header height. |
| Does grouping explain relationships? | Align related labels/values and give comparison enough width. Inspect the whole composition and individual panels; equal card geometry is a choice, not a default. |
| Is type doing useful work? | Deliberate title/body/label/value roles; readable chart labels, consistent units and numerals, long-label/fallback specimens. Fix optical alignment and ambiguous date ticks. |
| Does detail earn the interaction? | Detail adds evidence or a useful operation. Remove redundant disclosure or bind a justified additional query; do not invent analysis to fill it. |
| Does the brand shape the experience? | Show how typography, spacing, asset role and action vocabulary express the chosen direction while preserving data meaning. Color matching alone is insufficient. |
| Does the small layout preserve the task? | Actual narrow/zoom render plus keyboard route: selected identity, scope, useful return, contained table overflow and meaningful focus survive. |
| Does the main scene remain useful? | Frame stable analytical bounds; decorative scenery may crop. Check the first usable content view, readable selected evidence and exact-value companion when projected marks become small. |
| Are states coherent? | Selected, pending, current, empty, stale and failed remain distinct; visual polish must not obscure result or access uncertainty. |

Retain concrete findings and severity rather than a numerical beauty score. A materially unreadable chart, broken core task, hidden required scope or unresolved composition deviation keeps the affected craft case open. Lesser findings need explicit disposition. Report `pass`, `fail`, `blocked`, `not_run` or justified `not_applicable` per case. Craft completion does not close numerical, native interaction, access, performance, human usability, business acceptance or publication lanes. Let the orchestrator reconcile the requested completion scope; retain an honest candidate with gaps when prerequisites are unavailable.

When rendering is prohibited, continue the authorized implementation and have a separate reviewer trace the chosen experience in the source/spec: opening versus workspace, destinations, image roles, primary action, retained context and motion/static counterpart. Report this as source review and visual quality as unobserved. Numerical or asset checks cannot substitute for this experience review. If rendering later becomes available, begin with the entry, working view, meaningful transition and narrow state rather than an unrelated large test matrix.

Changing tokens/layout reopens affected visual/responsive cases; changing queries, filters or content also reopens affected analytical/interaction cases. Bind returned findings and retests to the exact revised version. No additional user approval is implied for already authorized reversible correction.
