# Critique and assessment for the design studio

Apply this guide to an exact artifact/version from the [curriculum](experience-curriculum.md). It adds teachable judgment to the existing [craft review](visual-craft.md) and [QA lanes](design-qa.md). It does not create an approval gate, a numerical beauty score or a claim of production acceptance.

## What a strong critique says

Use **observation → effect on the task → specific revision → evidence needed**.

Weak: “Make it pop; it looks generic.”

Useful: “The four equal summaries occupy the opening viewport, while the contributor comparison answering the stated question is below it. Give the comparison the primary region, subordinate the totals and put the period beside the finding. Review the revised opening view with long labels and the same data.”

Name the failure mechanism: competing focal points, unclear comparison, redundant interaction, dishonest scale, arbitrary decoration, weak grouping, poor optical alignment, unreadable annotation, lost context, unsupported narrative or motion without a useful relationship. A reviewer should propose a correction, not prescribe personal taste as a universal requirement.

## Anchored craft rubric

Before judging finish, reconcile the [experience brief](experience-brief.md). In the existing review, trace each consequential choice as `user requirement → selected design → implemented behavior → actual observation`. Start with the opening promise, primary action, working view, useful detail, context-preserving return and relevant narrow state. Record a missing choice separately from a supplied requirement the implementation dropped. A larger header, exact logo or functioning filter does not by itself satisfy an immersive-entry request.

Review the first assembled journey early, then give each consequential destination a disposition before claiming the whole experience complete. Ask what new evidence its primary action reveals and whether return preserves the investigation. A polished entry cannot compensate for a generic or unusable working view. Check named behavior directly: a calendar label does not prove a month grid, a projected scene does not prove camera exploration, and an iframe load does not prove playback. A useful fallback preserves the original unfulfilled requirement and its explanation.

For each material departure, retain intended/actual behavior, reason and disposition using existing deviation records. Source-only critique may establish architecture and identify omissions, but must leave unobserved craft/native cases open. A rendered still supports composition; a behavior claim needs exercised interaction. Keep positive user feedback attributable and separate from formal usability or production acceptance. Never mechanically score aesthetic quality or infer compliance from the presence of a CSS class, image or button.

Use qualitative anchors: **unresolved**, **functional**, **considered**, **resolved in the observed case**. Record `not_observed` when the evidence type cannot support judgment. Never total these into an objective quality score.

| Dimension | Functional but elementary | Considered / resolved evidence |
| --- | --- | --- |
| Analytical point of view | Charts display available fields but the key comparison is buried. | The thesis explains the question and comparison; the composition exposes it, and the reviewer can trace the claim to scope and data. |
| Composition | Uniform cards, weak grouping, no intentional dominance. | Hierarchy, proportion, alignment and density follow the task; alternatives differ structurally, and the chosen screen's tradeoff is explicit. |
| Encoding and chart finish | A plausible chart with default labels/axes and difficult comparison. | Suitable grammar, defensible scale, deliberate ordering, legible direct labels/units, meaningful missingness and an exact-value path. Complexity earns analytical value. |
| Brand and typography | Logo and color applied to an otherwise unchanged template. | Recognizable direction through type roles, rhythm, grouping, assets and interaction tone; actual logo/font/fallback requirements observed where applicable. |
| Narrative | Generic titles, unsupported positive claims or stale filtered commentary. | Evidence-bound finding, useful annotation and honest limitation; prose remains valid across the tested scope changes. |
| Interaction | Buttons work but detail adds little, or return loses the investigation. | Each action yields evidence or task progress; selected identity, scope, comparison context, keyboard route and recovery are demonstrated. |
| Motion | Entrance effects/spinners without a relationship, or an unimplemented storyboard. | The implemented transition explains a change, can be interrupted, preserves data truth and has a useful reduced/static equivalent. No-motion is valid when justified. |
| Resilience and inclusion | Only the ideal desktop state is considered. | Long labels, narrow/zoom states, focus, chart alternatives and applicable missing/partial/error/restricted states are observed and corrected; unrun checks are named. |

“Resolved” applies to the inspected scenario and evidence, not every user, viewport or future version. A written specification can demonstrate reasoning; only an actual rendering can support a visual observation. Native SDK behavior, numerical correctness, effective access, human usability and release status keep their own evidence lanes.

## Revision moves

| Finding | Useful correction | What to recheck |
| --- | --- | --- |
| Too many equal focal points | Subordinate summaries, enlarge the decisive comparison, simplify containment. | Opening hierarchy, scope visibility and the main task. |
| Decorative advanced chart | Replace it with the simpler encoding that answers the actual question, or obtain the missing evidence. | Comparison accuracy, data prerequisites and information gain. |
| Weak visual identity | Revisit type roles, density, composition, imagery and motion tone together; retain approved assets. | Brand specimen, actual logo/typography and narrow/fallback states. |
| Buried narrative | Replace a generic chart title with a scoped question/finding; place one precise annotation beside the relevant marks. | Claim validity under filtering, readable density and exact-value access. |
| Motion feels noisy | Use one focal transition, shorten delay, preserve context and remove unrelated effects. | Interruption, rapid input, reduced motion and target performance. |
| Pleasant but unhelpful detail | Add a justified decomposition, comparison or operation; otherwise remove the interaction. | Actual information gain, query scope and return path. |
| More panels, little new evidence | Use the [analytical coverage map](../../omni-data-analyst/references/analytical-coverage.md) to select a valid trend, comparison or exception; remove duplication. | Population/denominator consistency, unavailable facts and whether detail changes understanding. |
| Scenery overwhelms the analysis | Fit stable analytical bounds, crop decoration and provide readable selected evidence outside tiny marks. | Actual usable width/height, selected values, scale stability and unobstructed controls. |
| Dashboard feels like a landing page | Bring evidence into the working view and reduce decorative identity space. | Question/answer visibility without losing required brand identity. |
| App feels like a dashboard wrapper | Reconcile the selected experience mode, actual destinations and first encounter. For an immersive entry → workspace request, give each a distinct composition and useful connecting action. | Opening promise, destination changes, imagery roles, useful evidence and preserved context. A larger header alone is insufficient. |

Prioritize the defect with the largest consequence for the stated task. For a focused change, inspect affected elements and dependent cases only. A small documentation or styling edit does not require an unrelated regression suite. An existing native behavior, metric or access gate still applies when the change affects it.

## Practice progression

Keep a role-scoped practice record in the engagement, using ordinary design/QA evidence references. Suggested states:

1. **Available:** the installed skill can find the relevant lessons. This is documentation coverage.
2. **Practiced:** a worker produced an original exercise artifact for a named competency.
3. **Reviewed and revised:** a separate reviewer identified specific findings and observed the affected revision. Declare whether the evidence is specification, local render, local interaction or native target.
4. **Transferred:** the worker applied the reasoning to another domain, data shape or constraint without simply reusing the first layout; the new artifact received a scoped review.

For explicit training, record `role`, `competency`, `brief`, `artifact/version`, `evidence type`, `reviewer`, `findings`, `revision`, `retest` and `remaining limits`. A compact table is sufficient. Do not mark untouched roles practiced because they share a reference. A successful mock exercise does not certify native delivery. Independent agent critique is useful, but it is not a customer interview or human usability study.

The orchestrator can evaluate a fresh worker with one of these prompts without giving it the intended answer first:

- “Use the studio curriculum to design a dashboard and an App from Studio A for their different users. Return the thesis, competing structures, a resolved specimen specification, exact analytical checks and one motion storyboard. No live tenant writes.”
- “Use Studio B to decide which regional view supports a returns investigation. Explain what can and cannot be concluded and how your design exposes the denominator.”
- “Use Studio D to handle the requested advanced visuals using only the supplied monthly aggregates. Continue useful work and prepare only the missing backend requirements.”
- “Apply the relevant studio to a faithful native-dashboard migration with an unsupported animated source interaction. Preserve the user's surface and document the adaptation.”

Evaluate the returned work against the brief, not against keyword presence. Prefer a small number of meaningful rehearsals to broad phrase-matching tests. Do not present a rehearsed specification as an implemented or visually reviewed specimen.

## Motion and accessibility basis

The package adopts reduced/static equivalents as a design expectation. [WCAG 2.2 SC 2.3.3](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html) is **Level AAA** and addresses disabling nonessential interaction-triggered motion. [SC 2.2.2](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html) is **Level A**: its conditions distinguish automatically moving content from auto-updating information; the latter has no five-second exception. Apply the actual conditions rather than a blanket “under five seconds is accessible” rule. Checked 2026-10-22.

Also evaluate keyboard operation, focus, non-color meaning, text/graphic contrast, readable labels and an accessible chart alternative under the engagement's selected standard. A screenshot, successful automated scan or this curriculum cannot establish full accessibility conformance. Respect the user's tool restrictions; record unavailable native, assistive-technology and participant checks without substituting fictional observations.
