# Bounded responsibilities

Keep one owning orchestrator. Use these assignments only when they can proceed
independently; responsibilities need not imply four concurrent agents.

| Responsibility | Inputs | Output | Boundary |
| --- | --- | --- | --- |
| Inventory/acquisition | Selected source identity, independent inventory, original files, qualified operation scope | Pinned snapshot/capture and missing-evidence list | No inferred authority, refresh, save, SDK loading or source discovery beyond selection |
| WebI interpreter | Original specifications, provider definitions and control state | Element/placement/interaction mapping and unknown obligations | No formula equivalence from text similarity |
| Semantic collaborator | Universe/provider evidence, metric questions and independent expectations | Reviewed reuse route or versioned DMA request | No warehouse work under a semantic-only route; no assumed source-specific DMA producer |
| Independent QA | Originals, selected scope, candidate, exact observed states and results | Separate lane outcomes and exceptions | Producer output and hashes do not certify tenant access, rendering or acceptance |

Use the existing product owner for D/E decisions, data storyteller for traceable
narratives, designers for surface-specific layouts, BI/app engineer for
implementation and security reviewer for source/target authority boundaries.

Each task packet carries the exact source/candidate pins, source/platform
identifiers, scope, expected output, dependency gaps and stopping conditions.
A later change to source, state, candidate or backend baseline invalidates affected
comparisons. Preserve prior evidence rather than rewriting it.
