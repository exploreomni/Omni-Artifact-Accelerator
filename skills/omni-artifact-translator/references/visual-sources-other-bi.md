# Visual migration evidence: Tableau, Power BI, Looker, and Hex

Checked 2026-10-21 (America/Chicago). This is official-source research and a proposed acquisition design, not a tested tenant integration. Product documentation changes: pin the source product/API/tool-contract version when implementing. No customer system was accessed or changed for this review.

## Recommended architecture

Use **source BI → official MCP/API/CLI → preserved visual + definition + query + behavior evidence → OAA design and QA → native Omni candidate**. MCP is a transport and tool-discovery layer; it is not automatically an image exporter or a migration parser. A screenshot establishes visible appearance for one captured state. It does not establish formulas, complete rows, filter semantics, hidden interactions, effective security, or authoring permissions.

Recommended minimum capture bundle for each selected dashboard/page/app:

- Original IDs, parent IDs, product version, source revision/modified time, exact file hashes and acquisition method.
- Full-page render plus important chart/detail states, with viewport, page/tab, filter/parameter values, timezone, locale, capture time, freshness/cache settings, and declared user/persona. Keep failed or omitted renders in the denominator.
- Definition/configuration files, query/formula references, result samples and independent numerical expectations. Preserve truncation, omitted fields and unresolved dependencies explicitly.
- Control/action inventory, initial and changed states, expected recovery/reset behavior, and separate permission/access evidence. Do not retain credentials in the package.
- A mapping for each source object: retained meaning and familiar visual cues; proposed improvement; native Omni capability evidence; unsupported behavior and disposition; source-versus-target QA cases.

“Familiar but improved” is a design recommendation: preserve recognizable grouping, metric names, order and analytical tasks, then propose clearer hierarchy, accessible colors, spacing and responsive composition. Record each change separately from parity. A chart substitution must preserve the question, denominator and comparison; it is not established by visual similarity. The target remains native Omni dashboards or native Omni Apps unless another surface is explicitly selected. Consult the package's [Omni capability reference](../../omni-artifact-accelerator/references/omni-capabilities.md) before promising a target feature.

## Tableau

**Agent reach and identity.** Tableau's official hosted MCP at `https://mcp.tableau.com` serves Cloud customers across SKUs with OAuth 2.1 and the signed-in user's permissions; some tools need extra entitlements. Server customers use a self-hosted deployment. Confirm the answering site, especially for multi-site users. Server OAuth requires 2025.3 or newer. These are vendor-documented capabilities, not a live configuration finding. [Hosted MCP](https://tableau.github.io/tableau-mcp/docs/hosted-tableau-mcp), [OAuth and site selection](https://tableau.github.io/tableau-mcp/docs/configuration/mcp-config/authentication/oauth).

**Images and data.** `get-view-image` requires `viewId`; optional `width`, `height`, `format` (PNG default; SVG requires Server 2026.2.0+/REST 3.29+) and `viewFilters`. Filter field keys may include `vf_`; the tool adds it if absent. The normal response includes image data; configured S3 storage instead produces an expiring resource link. Preserve the downloaded original through an approved file-acquisition mechanism, not merely a temporary link. [MCP image contract](https://tableau.github.io/tableau-mcp/docs/tools/views/get-view-image).

`get-view-data` uses all-sheet `allData` on REST 3.30+ and a legacy CSV path on older versions. Retain per-sheet errors and the API version; do not equate this with unrestricted datasource rows. The tool does not paginate/truncate large results. [MCP view data](https://tableau.github.io/tableau-mcp/docs/tools/views/get-view-data).

**Direct export contract.** REST routes under `/api/{version}/sites/{siteId}` include `GET /views/{viewId}/image`, `GET /views/{viewId}/pdf`, and `GET /workbooks/{workbookId}/pdf`. Relevant parameters include `vf_<fieldname>`, `maxAge` (minimum one minute), image `resolution=high`, PDF `orientation` and `type` paper size. View `vizHeight`/`vizWidth` require REST 3.23+; view image `format` requires 3.29+. Use the exact endpoint's version and permissions, not one global export permission: workbook PDF requires Read/ExportImage and enabled downloads. A workbook without sheets shown as tabs can export only its default tab. Authenticate using the documented Tableau session header. [REST workbooks/views](https://help.tableau.com/current/api/rest_api/en-us/REST/rest_api_ref_workbooks_and_views.htm). The Embedding API also documents image, PDF and PowerPoint exports; this is a distinct authenticated integration, not an MCP PPT tool. [Embedding exports](https://help.tableau.com/current/api/embedding_api/en-us/docs/embedding_api_export.html).

**Metadata and gaps.** Metadata API GraphQL supports content, calculated-field/schema and upstream/downstream lineage discovery. Use it to bind visual IDs to source dependencies; it does not replace workbook layout/behavior definitions or effective-access testing. [Metadata API](https://help.tableau.com/current/api/metadata_api/en-us/index.html). Cloud 2026.1+ image export can render supported trusted extensions/Pulse while PDF/PPT can leave these blank; network-enabled extensions and transient selection/highlight behavior need separate review. [Tableau export restrictions](https://help.salesforce.com/s/articleView?id=001471348&language=en_US&type=1).

Recommended Omni review targets: LOD/table-calculation grain, parameters, sets, action chains, tooltips, dashboard zones, stories and extensions. Capture these as source behavior; do not infer their target implementation from pixels.

## Power BI

**Preferred inspection path.** Fabric IQ MCP is **generally available**, read-only and supports discovery, report/model metadata and DAX over the caller's authorized data. Endpoint: `https://fabriciq.svc.cloud.microsoft/v1/mcp/fabriciq`; private-link environments use `https://api.fabric.microsoft.com/v1/mcp/fabriciq`. It requires compatible Streamable HTTP/OAuth clients, Microsoft Entra delegated `Item.Read.All`, `Item.Execute.All` and `Dataset.Read.All`, and a supported tenant region. Service-principal/application-only authentication is unsupported. Existing RLS/OLS apply; Build permission and a workspace role are not prerequisites. Discover current schemas with `tools/list` and pin the available tool-contract version. Host compatibility must be independently qualified. [Fabric IQ MCP](https://learn.microsoft.com/en-us/fabric/iq/connectors/fabric-iq-mcp).

Do not confuse this with **Authoring MCP** (hosted preview; local generally available), which edits semantic models and executes DAX but does not edit report pages/layouts. [Authoring tools](https://learn.microsoft.com/en-us/power-bi/developer/mcp/remote-mcp-server-tools). The older **Consumption MCP preview** recommends Fabric IQ. Its documented `GetReportMetadata` includes pages, supported visuals, fields and filters, but omits action buttons, shapes and images; retain such omissions rather than treating a metadata result as the full report. [Consumption preview and metadata scope](https://learn.microsoft.com/en-us/power-bi/developer/mcp/remote-mcp-server-get-started).

**Export API.** `POST https://api.powerbi.com/v1.0/myorg/groups/{groupId}/reports/{reportId}/ExportTo` starts an asynchronous job. Supply `format` and `powerBIReportConfiguration`; use the status API and retrieve the completed file. The report configuration supports selected `pages` (`pageName`, optional `visualName`/bookmark), `reportLevelFilters`, `defaultBookmark`, `identities` and settings. A bookmark uses name or state, not both. Required delegated scopes include both a Report.Read[Write].All and Dataset.Read[Write].All option. [REST request/response schema](https://learn.microsoft.com/en-us/rest/api/power-bi/reports/export-to-file-in-group).

PDF/PPTX/PNG require Premium, Embedded or Fabric capacity; PPU is unsupported. PNG tenant export is disabled by default; multi-page PNG is a ZIP. Limits include 500 concurrent requests per capacity, five processed pages per report concurrently, 50 page/single-visual exports per job and 250 MB output. Retrieval URLs last 24 hours. Preserve explicit filters/bookmarks: personal bookmarks and persistent filters are unsupported. RLS export requires additional effective-identity permissions. Sensitivity-labeled PDF/PPTX cannot use service-principal export. Certain custom and embedded visuals, R/Python, Power Apps/Automate and other listed visual types are unsupported. [Export behavior and limits](https://learn.microsoft.com/en-us/power-bi/developer/embedded/export-to).

**Definition capture.** PBIR stores individual page, visual and bookmark JSON files; visual metadata includes position, formatting and query, while page/report metadata includes filters. Preserve `definition.pbir` model binding, theme/static/custom-visual resources and semantic model separately. Configuration files may contain actual filter values and must be handled as data. [PBIR report structure](https://learn.microsoft.com/en-us/power-bi/developer/projects/projects-report).

Recommended Omni review targets: DAX context/aggregation, calculation groups, field parameters, bookmarks, drill-through, cross-highlighting, visual interactions, custom visuals, mobile layout and RLS/OLS. An accessible Fabric IQ result or administrator export does not establish another persona's access.

**Current acquisition boundaries.** Fabric `getDefinition?format=PBIR` returns original inline Base64 parts or a long-running operation. Despite being a read, it requires report write permission/scopes; labels are not returned, and encrypted-label rights require separate review. [Get Report Definition](https://learn.microsoft.com/en-us/rest/api/fabric/report/items/get-report-definition). REST ExecuteQueries has different permissions from Fabric IQ: Read + Build and an enabled tenant setting. Inspect response-level errors and truncation even on HTTP 200. [ExecuteQueries](https://learn.microsoft.com/en-us/rest/api/power-bi/datasets/execute-queries).

Microsoft also documents a [Report skill](https://learn.microsoft.com/en-us/power-bi/developer/agentic/power-bi-report-skill-overview) and [report-author CLI](https://github.com/microsoft/skills-for-fabric/blob/main/skills/powerbi-report-cli/references/authoring/powerbi-report-author-cli.md) for definition inspection and host-specific preview. Keep those optional capabilities separate from OAA's source-only wrapper; metadata inspection is not a screenshot, and local-definition preview is not proof of published state. See the [Power BI source contract](powerbi-source-contract.md) and [run guide](../../omni-artifact-accelerator/references/powerbi-visual-run.md) for this package's actual implementation and limits.

## Looker

**Agent reach.** The Looker-managed MCP server is **Preview** for Google Cloud core and original Looker-hosted instances; customer-hosted instances are excluded from this preview. Endpoint: `{LOOKER_INSTANCE_URL}/mcp`, OAuth 2.1. Admins register the client and explicitly enable tools (all disabled initially); access inherits the user. Fine-grained OAuth scopes and dynamic client registration are not supported in this preview. Existing query/API quotas still apply. [Managed MCP](https://docs.cloud.google.com/looker/docs/mcp). Official tool contracts include `query_sql`, `query_url`, `run_dashboard` and `run_look`; these must not be mistaken for screenshot tools. [MCP tool settings](https://docs.cloud.google.com/looker/docs/reference/looker-api/latest/types/McpTools). Google's [MCP Toolbox route](https://docs.cloud.google.com/looker/docs/connect-ide-to-looker-using-mcp-toolbox) is a separate deployment/configuration choice; enable only the required read/query tools for migration discovery.

**Render contract.** API 4.0 documentation (latest reference observed: 4.0.26.20) exposes `POST /render_tasks/dashboards/{dashboard_id}/{result_format}` for `pdf`, `png` or `jpg`. Body: `dashboard_filters` in URL query format, `dashboard_style` (`single_column`/`tiled`), optional `tab_ids`. Query parameters: `width`, `height`, `fields`, `pdf_paper_size`, `pdf_landscape`, `long_tables`, `theme`. Poll Get Render Task, then fetch Get Render Task Results only after success; retain failure/status detail and executing user. A valid theme can select the embedded rendering context, so record it. [Create Dashboard Render Task](https://docs.cloud.google.com/looker/docs/reference/looker-api/latest/methods/RenderTask/create_dashboard_render_task).

PDF expanded-table output is bounded (50,000 rows per table/200,000 cells per dashboard); PNG does not inherit PDF paper/expanded-table behavior. Customer-hosted rendering requires appropriate Chromium setup. [Rendered-format limitations](https://docs.cloud.google.com/looker/docs/best-practices/rendered-format-options-downloading-delivering-dashboards).

**Definition capture.** Get Dashboard returns elements, queries/Looks, filters and layouts, including filter dependencies/configuration. The optional `fields` projection can omit needed evidence; preserve the request as well as the response and obtain referenced objects. [Dashboard API](https://docs.cloud.google.com/looker/docs/reference/looker-api/latest/methods/Dashboard/dashboard). Recommended additional dependencies: LookML commit/model definitions, merged-result sources, dynamic fields/table calculations, visualization configuration, user attributes/access filters, links/actions and custom visualization contracts. These dependencies need explicit review; neither the renderer nor the current OAA offline importer resolves all of them.

Recommended Omni review targets: Explore grain and joins, table calculations/pivots, merged results, filter listeners, dashboard links, custom visualizations and Liquid/user-specific behavior. Screenshot parity does not certify equivalent LookML or access policy.

**Reuse reference, not an adopted execution path.** Omni's official [Looker migration guide](https://docs.omni.co/guides/migrations/looker-to-omni-skill) provides useful source-inspection and field/filter mapping patterns. Its sample builder calls `delete_existing_by_name()` across all accessible folders and uses unstable beta export/import endpoints; the guide identifies newer v2 Documents layout/control support. Do not copy that destructive build loop into this workflow. Reuse inspected mapping ideas through the package's separately qualified target draft/review route.

## Hex

**Agent reach.** Official Hex MCP is **beta**, available on Team/Enterprise, with OAuth at `https://app.hex.tech/mcp` (use the correct regional/custom host). Tools include project search, project/cell inspection and `get_cell_image` for rendered chart PNGs, alongside mutation/run tools that are not needed for passive capture. Cell listings use draft notebook state, default 25/max 100 per page with cursor pagination. They omit chart/input configuration and section nesting. Optional sharing metadata is useful context, not effective-access proof. Published and draft identities must remain distinct. [Hex MCP contract](https://learn.hex.tech/docs/api-integrations/mcp-server).

**Files and visuals.** Project export supports Hex YAML and IPYNB; prefer the native YAML plus its schema for configuration preservation, not IPYNB as a claim of App parity. [Project import/export](https://learn.hex.tech/docs/explore-data/projects/import-export). The official CLI manages projects/cells/runs and supports JSON output; Team/Enterprise and enabled API access/token setup are prerequisites. It is actively evolving: pin `hex --version` and inspect that version's `--help` before using an export command. A CLI is not evidence that every App state can be exported. [Hex CLI](https://learn.hex.tech/docs/api-integrations/cli).

Published Apps support UI PDF snapshots for authenticated users on Team/Enterprise. Each tab becomes a page, with **a maximum of six tabs**; additional tabs are omitted. Admins can disable export; anonymous public viewers cannot use it. Scheduled PDF/PNG delivery is a separate sending workflow and is outside passive migration capture. [App PDF](https://learn.hex.tech/docs/share-insights/apps/export-as-pdf). This review did not verify a public full-App PDF/PPT API; do not invent one or confuse chart-cell PNG with a complete App screenshot.

Recommended Omni review targets: App grid/tab order, reactive execution, Python/R output, input defaults/dependencies, SQL cells, components, cache/run state, writeback and sharing/access. Retain readable analytical compositions where native Omni supports them; classify executable logic and unsupported interaction separately before choosing an App or dashboard.

## Existing package implementation versus proposed work

The implemented [offline inventory contract](inventory-contract.md) accepts supplied evidence; it makes no network calls or native conversion claims:

| Implemented reader | What it preserves | Explicit boundary |
|---|---|---|
| `looker-api` | Supplied Dashboard object, embedded query/Look references, filters/layout components | No authenticated acquisition; merged results/SQL dependencies and completeness unresolved |
| `dma-inventory`: Tableau | Pinned DMA inventory of workbooks/dashboards/worksheets/parameters, zones/shelves/filter/table-calculation evidence | Source actions/stories, rendering and live permissions still need review |
| `dma-inventory`: Power BI | Pinned enhanced PBIR inventory of projects/pages/visuals/filters | Inspected extractor profiles `tableEx`; not general chart/PBIX/bookmark/field-parameter support |
| `dma-inventory`: Hex | Pinned projects/cells, App layout, cell IDs/configuration/chart specifications | No reactive execution, component/input or access verification |
| `normalized-inventory` | Supplier-declared manual evidence with visual/query/layout/filter/interaction/security/content facets | Not a native parser; missing facets become gaps, references are not fetched |

**Proposed package work:** official acquisition adapters with read/query/export allowlists; capture manifests and export-job polling; parser/schema expansion from preserved definitions; visual comparison and analyst behavior tests. Keep acquisition separate from DMA's semantic/model parsing and from OAA's immutable evidence projection. An imported source inventory, MCP connection or local candidate is not source/target tenant acceptance. Root orchestration must still retain numerical, native interaction, effective-access and business gates.

## Pilot acceptance criteria (recommended)

1. One representative source dashboard/App includes all selected pages/tabs and explicit omitted/unsupported objects; capture identifiers and hashes reconcile with the inventory denominator.
2. The same declared filters, time context and persona produce independently checked source numbers and an Omni candidate with explained differences; no unverified formula is promoted from an image.
3. The package includes at least one changed-filter state, detail/navigation case and restricted-persona case; unavailable source or target execution remains pending, not passed.
4. The design review distinguishes retained familiar cues, approved improvements, unsupported behavior and native-target evidence. Static success cannot close native interaction, security or business acceptance.
