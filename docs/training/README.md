# Getting started with the Omni Artifact Accelerator

**Turn a business question into a data experience people can use.**

This self-guided introduction explains what to provide, how the agents work together, and how to review the result. You can read it before setting anything up. You do not need to write code to supply requirements, choose a design or review a delivery; an approved agent host and technical access are needed to build.

## Follow the learning path

| Lesson | You will learn | Observable checkpoint |
| --- | --- | --- |
| 1. [Understand the accelerator](01-understand.md) | What the package does, who does what, and which output fits your task | Explain the difference between the host, accelerator and Omni |
| 2. [Prepare your first engagement](02-prepare.md) | Select the source, check access and give your agent a useful brief | Identify the exact package copy and private engagement folder |
| 3. [Go from data to a story](03-data-and-story.md) | Verify access, analyze the data and make claims traceable | Explain one supported finding and one limitation |
| 4. [Choose the experience](04-choose.md) | Set the quality bar, answer the design interview and select from three concepts | Choose a concrete direction with observable requirements |
| 5. [Review and deliver](05-review.md) | Assess numbers, complete journeys, visual quality and publication readiness | Distinguish a local candidate from a verified live result |
| 6. [Resume, migrate and collaborate](06-continue.md) | Request focused changes, migrate source behavior and work with Data Model Accelerator | Resume the same engagement without repeating discovery |

Read in order, or choose an entrypoint. Business reviewers can start with lessons 1, 4 and 5. Builders should also complete lesson 2. Migration teams should read lesson 6 before starting a new engagement, particularly when they already have a backend handoff.

The examples are generic learning prompts, not a required visual template or evidence of a completed customer deployment. Completing this guide does not qualify a host, connector or native runtime.

The roles are responsibilities, not a requirement to launch a separate agent for every box. The orchestrator shares only the context each task needs and keeps the complete engagement current. Independent creative and QA duties remain separate from the work they assess.

## Keep these three rules in mind

1. **Data before design.** Confirm access, supported analysis and the story before choosing the product experience.
2. **You choose before the build.** Review three viable visual concepts; the agent records your actual choice and resolves the detailed design before coding the product.
3. **Evidence before completion claims.** Correct source, rendered quality, live behavior and your acceptance are different checks. Missing checks stay visible.

## About the guide and diagram

This guide follows the six-lesson structure of the [Data Model Accelerator introduction](https://github.com/exploreomni/Data-Model-Accelerator/tree/main/docs/training). It teaches this package's current workflow; setup rules are specific to this repository.

The editable SVG uses the Omni branding guidance's core palette, flat rounded shapes and accessible text contrast. It deliberately uses an **Arial/system sans-serif fallback**, with no downloaded fonts, logo substitutes or external assets. GitHub controls the surrounding Markdown typography. The diagram is instructional artwork, not an application screenshot or proof of execution.

Maintainers: when workflow behavior changes, update the diagram, its text alternative and the affected lessons together. Keep credentials, customer evidence, rehearsal outputs and planning documents outside this guide and repository.
