# 1. Understand the accelerator

[Learning guide](README.md) · [Next: prepare](02-prepare.md)

**Outcome:** you can explain what the accelerator adds and choose an appropriate starting point.

## Three parts work together

| Part | What it does | What it does not establish by itself |
| --- | --- | --- |
| Your approved AI host | Runs the conversation, reads files and uses the tools available to your account | A repository link alone does not load every skill or connect a tenant |
| Omni Artifact Accelerator | Supplies specialist instructions and local helpers for requirements, evidence, stage checks and handoffs | It is not a standalone BI service or a permanently running agent team |
| Omni | Provides the connected models, governed queries and native destination for the selected artifact | An accessible model or successful write does not prove the finished experience works for its intended users |

The orchestrator coordinates the work inside your host. Using Omni's CLI or API does not implicitly invoke Omni AI/Blobby. Actual model usage and tool execution depend on the selected host and route; the package does not promise a fixed bill or automatic access.

## Pick the output by the job

| Output | A useful starting task | What to expect |
| --- | --- | --- |
| Native dashboard | Monitor performance, compare groups and drill into exceptions | Deliberate chart composition, filters, definitions and review evidence |
| Native App | Investigate an entity, follow a story or complete a multi-step analytical task | Purposeful navigation, interaction states and a cohesive visual experience |
| Native Reports Beta | Read or export a page-precise operational report | Page, grouping and output specifications; native authoring must be qualified for the target |
| Dashboard and App | Monitor an issue, then investigate it in depth | Explicit responsibilities for both surfaces rather than two copies of the same layout |

A dashboard is a valid product when it fits the task. An App should earn its navigation and interactions. “Premium” does not automatically mean 3D, a cinematic opening or a particular library. The agent should propose a form that serves your decision and preserves your quality expectations.

## Meet the responsibilities

| Responsibility | What it owns |
| --- | --- |
| Orchestrator | One current engagement, stage order, task routing and reconciliation |
| Product owner | Your goals, interview notes, priorities and the experience promise |
| Data analyst and BI engineer | Metric meaning, source evidence, query bindings and analytical checks |
| Data storyteller | Supported claims, explanatory flow and behavior when the evidence changes |
| App, dashboard or report designer | Composition and behavior appropriate to the selected surface |
| Branding and design systems | Approved assets, typography, color semantics, control quality and accessibility |
| App engineer, BI engineer or report builder | Implementation appropriate to the native target |
| Security, UI/UX, product owner and independent QA | Four distinct review perspectives on the current candidate |
| Motion designer and 3D modeler | Conditional expertise when motion or spatial exploration helps the task |
| Artifact translator and source specialist | Migration inventory and source-specific behavior |
| Backend handoff | Versioned requests and responses with Data Model Accelerator or a model owner |

These responsibilities do not imply that all specialists run on every request. The host can perform work inline or delegate bounded tasks. Independent critique and QA must retain their separation; giving an agent a role name is not proof that a review occurred.

## A few terms you will encounter

- **Engagement:** the private working folder containing your brief, decisions, evidence and candidates.
- **Governed query:** a query bound to reviewed definitions and the relevant access context.
- **Concept:** one concrete proposed product direction, with representative visuals and behavior.
- **Candidate:** a particular version of the artifact being reviewed; it is not automatically published or accepted.
- **Handoff:** a scoped package of requirements, evidence and unresolved questions for another responsibility or team.

**Checkpoint:** name the output your team needs and the action a user should be able to take with it. You can change the provisional surface as evidence develops; do not use a surface change to bypass recorded workflow gates.
