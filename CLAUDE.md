# Start an artifact engagement

For a request to create, redesign or migrate an Omni App or dashboard, first read
[the orchestrator](skills/omni-artifact-accelerator/SKILL.md) and follow its
[execution entry procedure](skills/omni-artifact-accelerator/references/execution-workflow.md).
Repository maintenance, a focused repair and review-only requests retain their own scope.

For repository-only work, use [explicit engagement entry](skills/omni-artifact-accelerator/references/engagement-entry.md)
and read the generated reference to the exact checkout and existing sibling
engagement. An entry is not installation, host configuration or qualified authority.

Record actual source identity and ownership before the first new artifact stage.
Use the current trusted package's host-entry preflight to compare the loaded path
with the requested release and inventory raw CLI/API/MCP/shell write routes. An
older installed entry cannot certify itself as latest. Reuse the receipt and
report advisory limits; never activate an update automatically.
Use the execution procedure's `run-start`, incremental `run-guidance` and
stage-aware `phase-check` requests. Honor `current_checkout`, `pinned_revision` or
`latest_main` explicitly; an existing directory is not evidence of latest main.
The bounded `source-check` reads the configured HTTPS origin without fetching,
installing or activating code. A mismatch is a source gap, not an automatic update.

Use the [executable A–F gates](skills/omni-artifact-accelerator/references/stage-gates.md).
Never code before the actual user chooses one of exactly three options and detailed
design is resolved. Check the stage before specialist dispatch and use guarded
build/freeze plus candidate-bound consulting reviews. Do not route around a blocked
gate through raw writes, changed project mode or local approval flags. For ordinary
chat, use the explicit conversation-evidence policy and record the actual reply
against the exact options. Strict host verification remains available without
automatic fallback. Conversation evidence never grants native write authority.

Present three concrete visual concepts at equal accepted ambition, retaining the
same analytical scope. Label source-only specimens as unrendered; do not substitute
three prose pitches. Preserve quality intent through the selected design and four
candidate reviews. Responsibilities may share workers when independence permits;
no library, dimensional treatment or extra team is mandatory.

New non-report `init` engagements require a sourced or scoped-delegation D promise
under [experience continuity](skills/omni-artifact-accelerator/references/experience-continuity.md).
Creative mode proposals resolve through the existing concept choice, without a
second interview. Dashboard/monitoring work remains valid by task. The first
journey is an early checkpoint; final PO/UI/UX fit coverage retains all promised
outcomes and consequential destinations, including gaps outside a bounded slice.

Report authorized candidate preview, verified selected scope and publication
separately. Preview may enable later native observation; a successful write or
readback cannot close unrun visual, access or human cases. Retain open findings.

For new Apps, follow [candidate release](skills/omni-artifact-accelerator/references/app-release.md).
Carry first-view/action/result concepts and actual hybrid amendments into the
selected design. Annotate each visible live/snapshot/scenario consumer and retain
its independently checked expectation. Host HTML guidance must use this selected
target and journey while preserving its sandbox/security rules; a local report
example does not prescribe the native App's composition or data source.
Use guarded native preparation and exact whole-draft publication. A raw upload is
outside the managed path and cannot be reported as accelerator-qualified release.

Preserve [project boundaries](AGENTS.md). A repository URL or this file does not
configure MCP, launch specialists, authorize dependencies or enforce other tools.
Identify the actual host and consumed files. Use existing approved tools; do not
install or activate the package to make a test pass. When this file is unavailable
in a connected chat, use the explicit entry instructions in the README.
