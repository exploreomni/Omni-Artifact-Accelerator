# Project execution boundaries

For substantial Omni artifact creation/redesign/migration, enter through
[the orchestrator](skills/omni-artifact-accelerator/SKILL.md) and its
[execution procedure](skills/omni-artifact-accelerator/references/execution-workflow.md).
Repository maintenance and focused repairs do not require a new artifact engagement.

For repository-only work, use [explicit engagement entry](skills/omni-artifact-accelerator/references/engagement-entry.md)
to bind the exact checkout and declared host to the existing sibling engagement.
Explicitly read its reference; preparation neither installs code nor qualifies
host enforcement. Preserve blocked access as a gap rather than inventing readiness.

Before the first new artifact stage, record the actual package source, original
request and execution-contract path with `run-start`. Respect the requested source:
`current_checkout` records what is present; `pinned_revision` requires that clean
revision; `latest_main` requires a current read-only `source-check` receipt and a
matching clean checkout. Never reuse an older directory while claiming latest, or
fetch/install/activate a replacement automatically. Follow the execution procedure
for incremental `run-guidance` receipts and `phase-check`; recorded reads are
declarations, not proof of reading or comprehension. Resume the existing engagement
and preserve older records rather than rewriting its history.

For artifact work, obey the [executable A–F gates](skills/omni-artifact-accelerator/references/stage-gates.md).
Inspect stage status before dispatch; never code a new product before the actual
user selects one of exactly three options and detailed design is resolved. Use
guarded assembly/freeze and candidate-bound reviews. A blocked gate is not permission
to switch to raw shell/file/API authoring, change mode, delete policy or synthesize
an approval. For ordinary chat, explicitly configure the conversation-evidence
selection policy and retain the actual user reply against the exact options.
This permits local design/coding; it does not authenticate an approval or authorize
native writes. Existing strict engagements never fall back automatically. The
host must qualify privileged execution and enforce routes outside package helpers.

For new products, keep the same accepted analytical scope and quality ambition in
all three concrete visual concepts. Prose descriptions alone are insufficient;
source-only SVG specimens remain explicitly unrendered. Resolve the selected
experience handoff before code, with design-system and independent creative duties
assigned where required. These are responsibilities, not a requirement for more
agents, libraries, 3D or a fixed layout. Do not treat a guided story or frequent-use
audience as permission to lower craft expectations.

New non-report `init` engagements require the D promise in
[experience continuity](skills/omni-artifact-accelerator/references/experience-continuity.md).
Recover sourced intent or actual scoped delegation; creative mode hypotheses wait
for the existing concept choice. A task-appropriate dashboard remains valid.
PO/UI/UX fit coverage must retain every promised outcome and consequential journey,
even when an early representative slice or bounded correction is reviewed.

Distinguish local preparation, an authorized candidate preview, verified selected
scope and publication. A preview may be needed to obtain native observations;
publication/readback and four source consultations do not establish rendered
quality, effective access or human acceptance. Retain outstanding findings and
unobserved lanes in the handoff. Never broaden dependency or native-write authority
to satisfy a quality check.

Use [host-entry preflight](skills/omni-artifact-accelerator/references/engagement-entry.md#inspect-the-host-entry-first)
from the trusted current source before dispatching an installed skill. Compare
the actual loaded path, honor pinned/offline source choices and inventory raw
write routes. Reuse its receipt; do not claim enforcement from an agent-written
configuration. New Apps use [candidate release](skills/omni-artifact-accelerator/references/app-release.md)
for concept action sequences, visible data consumers and exact whole-draft
publication. Host-specific HTML examples remain subordinate to the selected
native target and experience, without weakening host security requirements.

Follow the workspace instructions and the [dependency policy](skills/omni-artifact-accelerator/references/dependency-policy.md).

- Never install, import/load, vendor, update or activate a third-party package, library, skill, runtime image or decoder without Austin's explicit sign-off covering that exact action and dependency closure. Prior availability is not approval. This applies to local tools, subagents, CI, MCP and browser/CDN imports.
- An implementation or push request does not authorize dependency acquisition or activation. Prepare the exact reviewable request first. Do not auto-repair missing dependencies.
- No Blender code, APIs, scripts, add-ons, copied node setups, dependencies or `.blend` processing. Conceptual learning is not implementation provenance.
- Source review and original first-party code using the existing runtime's standard library may proceed in scope. Use Python `-I -S` for source-only checks so site packages/startup hooks are not imported. Do not run the full dependency-backed suite until authorized.
- The optional spatial harness accepts declarative data. No arbitrary generated scripts, package names, plugin loading, tenant credentials or network access in a modeling worker. No host fallback when isolation is unavailable.
- An agent-writable file, boolean or approval reference cannot confer authority. Production execution and active skill installation remain disabled until a trusted host gate is qualified.
- Keep runtime, security, numerical, visual and native qualification distinct. Source checks and synthetic fixtures cannot certify isolation or visual quality.
- Preserve the user's CLI/API-only constraint. No browser/headless-render workaround. No live app changes or push without corresponding authorization.

Planning documents, customer assets, real query results and release archives belong outside this repository. Maintain useful product instructions and original fixtures inside it.
